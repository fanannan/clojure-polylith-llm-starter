# IDEA: Demand Forecast Replenishment

## 背景

小売店の SKU 別売上履歴から、次の 2 週間の需要を予測し、発注提案を出したい。
今は担当者が CSV を見ながら経験で発注していて、欠品と過剰在庫がどちらも起きている。

## 作りたいもの

日別売上 CSV、現在庫、リードタイム、安全在庫の目安を入力し、SKU ごとに発注数量と理由を出すバッチ処理。
需要予測そのものは Python の機械学習ライブラリを使ってよい。
Clojure 側では入力検証、業務ルール、発注提案、レポート生成を扱いたい。

## 期待していること

予測値だけでなく、在庫・リードタイム・安全在庫を加味した発注提案にしたい。
発注しない SKU についても、なぜ発注不要なのか分かるようにしたい。
予測精度は MAE や MAPE のような分かりやすい指標で確認したい。

## 制約・好み

GPU や外部サービスは使わない。
最初は小さな CSV fixture で完結させたい。
Python は ML kernel として使い、プロダクト構造や検証導線は Clojure Polylith 側で持ちたい。

## 迷っていること

どの予測モデルを使うべきかはまだ決めていない。
SKU の季節性や欠損データへの対応は、最初は簡単でよい。
将来は複数店舗に広げたいが、最初からマルチテナント設計にはしたくない。
