# IDEA: Webhook Idempotency Processor

## 背景

外部決済サービスから webhook を受けて注文状態を更新したい。
同じ event が複数回来ることがあり、二重更新や二重通知が怖い。

## 作りたいもの

署名を検証し、event を正規化し、注文状態を更新する小さな webhook 受信サービス。
処理済み event は再処理しない。
失敗した event は理由を残し、後から再処理できるようにしたい。

## 期待していること

同じ event-id が何度届いても、業務処理は一度だけにしたい。
署名が不正なものや payload が壊れているものは受け付けたくない。
処理結果はあとで追えるようにしたい。

## 制約・好み

最初は外部 DB や実決済サービスにはつながなくてよい。
ローカルで再現できる fixture とテストを重視したい。
HTTP API として動かせると嬉しい。

## 迷っていること

保存先はまだ決めていない。
本番 retry の設計は最低限でよいが、あとで拡張できる形にしたい。
どの決済サービスにも固定しすぎたくない。
